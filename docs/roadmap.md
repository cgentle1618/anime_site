# Roadmap

Last verified: 2026-09-07

## What this is for

This file replaces `roadmap.md`. It is the one place that answers three questions: what has already shipped (so nobody re-plans it), what is being worked on right now, and what was consciously left undone. The "Done" log is one line per feature, newest first, distilled from the git history and the retired plan. "Next" is empty on purpose until a piece of work is picked up. "Deferred / known debt" lists things the code still does the awkward way; each line was checked against the source on the verification date, so if a line is stale the code moved and the line should go.

The rule from `CLAUDE.md` still applies: when implementing from this file, pause and ask for permission after each step or set of steps, record progress in the "Next" section only, and do not rewrite the plan itself.

| 2026-09-06 | **Steam integration for games**: `game` becomes the first media type whose Fill merges two sources — IGDB (public metadata) and Steam (a personal-account source) — in one run. IGDB's `external_games` now supplies the Steam appid, so `steam_appid`/`steam_link` fill automatically; **IGDB writes them, not Steam** — Steam only reads the appid as its key — and the pair is only adopted when the entry has neither, so a hand-typed link is never paired with IGDB's appid for a different edition. Steam's storefront (`store.steampowered.com/api/appdetails`, no credentials) fills `metacritic_score` (the critic metascore only; `metacritic_user_score` stays hand-typed, since Steam does not publish a user score), `price_original_us/jp/tw` (fill-only), `price_current_us/jp/tw` (overwritten every run) and `achievements_total`. Steam's Web API (`STEAM_API_KEY` + `STEAM_ID`, currently unset) fills `hours_played` and `achievements_earned`; without those credentials the storefront half still fills on its own. A new tristate `steam_progress_sync` column locks those two personal-progress columns — `False` means Steam never writes them (a game owned on Steam but played elsewhere), `None`/`True` means it may — and a zero playtime or unknown achievement count never overwrites an existing value either. `game` gains its first bulk Replace, re-running the Steam half only (IGDB carries nothing that drifts), and joins Replace All. Steam writes columns only, never tags or credits, so it never touches the alias layer. Nine fields across the app are now pipeline-overwritten rather than three: `mal_rating`, `mal_rank`, `imdb_rating`, plus `metacritic_score`, the three `price_current_*` and the two progress columns. Migration `gs1p2r3o4g5`. Plan: `docs/superpowers/plans/2026-09-06-steam-integration.md`, spec `docs/superpowers/specs/2026-09-06-steam-integration-design.md` |
| 2026-09-06 | **Metacritic scores on a game**: two columns rather than one, because Metacritic publishes two figures on two scales — `metacritic_score` (Integer, the critic metascore out of 100) and `metacritic_user_score` (Float, the user score out of 10). Neither is derived from the other, and neither is `my_rating`, which stays my own judgement. No CHECK on the ranges, matching every other game numeric: an out-of-range value is a typo to correct, not data that breaks a derivation. Manual entry only for now — nothing lists them in `GAME_FIELDS_TO_FILL`, since an unfillable column would leave every game permanently "needs filling"; an IGDB `aggregated_rating` autofill is a later change and needs no migration of its own. On the frontend they sit in a new Add/Modify **Rating** section directly under Classification, which also takes `my_rating` off the Status row - the three verdict fields on a game read together, and the registry's `Ratings` group moves with them so /defaults matches the form. They also render as a row in the game detail page's Information card via a new exported `outOf(value, max)` helper that keeps each denominator attached (`96 / 100` beside `8.6 / 10`), and as a **Metacritic** sort on `/library/game` where an unscored game sorts below a genuinely bad one. Migration `gm1e2t3a4c5`, stacked on the head rather than editing `g1a2m3e4s5` in place, so a database that already migrated still gets the columns. |
| 2026-09-06 | **Game platforms are a tag, not a source**: which platform a game is on (`PlayStation`, `Nintendo`, `Xbox`, `PC`, `Mobile`, `Browser`) is the fifth game tag field `game_platform` / category `Game Platform`, not a `media_source` access row — a game carries no availability tristate and no per-platform link, and which copy was owned is already `game_copy`.
